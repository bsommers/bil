§1

Three words, three obligations

The name is the method. Every claim bil makes is bounded in what it covers, anchored by an invariant, and stated in logic.

Bounded

Honest about reach

Each proof obligation is either PROVED by Z3 or reported as BOUNDED with the number of samples tried. bil verify exits 1 on a bounded-only result unless you pass --allow-bounded.

Invariant

True before, true after

Loops carry an invariant and a variant. A system carries invariants that must hold initially and survive every nondeterministic transition. A failure comes back with a shortest counterexample trace.

Logic

First-order, typed, ontological

forall / exists over ranges and concept hierarchies (BFO-compatible), inside Hindley–Milner type inference. ASCII or Unicode: => and ⇒, forall and ∀.

§2

One source, one IR stack, many checkers

§3

Source, then judgment

Both panels are real: source from examples/, output trimmed from the CLI. Nothing here is mocked.

examples/gcd_refinement.bilrefinement
spec gcd_spec(a: Int, b: Int) -> Int
  requires a > 0 && b > 0
  ensures  result > 0 && (a % result == 0)
           && (b % result == 0) && …

fn gcd(a: Int, b: Int) -> Int
  refines  gcd_spec
  requires a > 0 && b > 0
  ensures  …
=
  do x = a, y = b
    invariant x > 0 && y > 0
              && gcd_val(x, y) == gcd_val(a, b)
    variant   x + y
  :
    x > y -> x := x - y
  [] y > x -> y := y - x
  od
  then x

examples/mutex_protocol.bilsystem
system PetersonMutex {
  state p0: Phase = Idle
  state p1: Phase = Idle
  state turn: Int = 0

  invariant MutualExclusion:
    !(p0 == Critical && p1 == Critical)

  temporal StarvationFreeP0:
    (p0 == Trying) ~> (p0 == Critical)

  transition
    p0 == Idle -> p0 := Trying, turn := 1
  [] p0 == Trying && (p1 == Idle || turn == 0)
       -> p0 := Critical
  [] …
}

§5

What emit-verus proves, and what it does not

For each system, Verus checks every emitted transition step. We state the boundary plainly.

Proved

  • Each safety invariant is inductive over the emitted step_<i> functions.
  • All 14 examples/domains systems emit Verus that verifies.
  • Verus rejects the 6 seeded safety bugs with “postcondition not satisfied”.

Not covered

  • LTL liveness (~>, eventually). That stays with model-check.
  • Runtime-axiom bugs. An axiom is assumed, not proved.
  • That your hand-written Rust refines next. That proof is yours.

Of the 11 seeded bugs, 6 are in scope. The other 5 are classified out of scope with reasons in tests/verus_emit.rs: 2 violate liveness and 3 are runtime-axiom bugs. Pinned Verus: 0.2026.10.26.d17fbd0. Numbers inside example models are illustrative.
