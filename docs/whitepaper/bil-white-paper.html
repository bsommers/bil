Bounded Invariant Logic in Practice

Proving the safety logic of fourteen industrial, medical and security designs before they run, with every requirement traced to a qualified source.

bil projectModels: examples/domains/Sources: docs/whitepaper/CITATIONS.md

Abstract

Accident and recall investigations keep finding the same class of defect: interlocks, alarms and protocol state machines whose logic was wrong in the design, long before any code ran. bil (Bounded Invariant Logic) is a statically typed language that puts domain ontologies, first-order specifications, Dijkstra's guarded commands and reactive state machines in one source file, and checks them with weakest-precondition proofs, SMT solving and explicit-state model checking. The same file then runs on an interpreter, a bytecode VM or as a native binary.

This paper applies bil to fourteen domains, from semiconductor anneal control after spectroscopic ellipsometry to surgical teleoperation, process safety instrumented systems and TLS-style handshakes. Each model encodes requirements taken from standards, regulator reports and peer-reviewed physics, and each source is graded and cited. Across the suite, z3 proves all 147 verification obligations with none left to sampling, the model checker explores 308 states in 16 systems and proves 14 liveness properties, and all three execution back ends print identical results. Ten one-line seeded bugs, each modeled on a documented failure mode, are all caught with a concrete counterexample. The research also corrected four of our own first drafts, which is the strongest argument in the paper for tying formal models to primary sources.

1Why designs fail

The failures that matter most in safety-critical systems are rarely arithmetic slips. They are logic errors in how a system reacts to events: an alarm that does not latch, a state machine that accepts a message out of order, an interlock that is correct for each fault alone but not for two faults together.

  • Medical devices. Between 2005 and 2009 the FDA received about 56,000 adverse-event reports for infusion pumps and oversaw 87 recalls, 14 of them Class I. Its analysis traced many problems to design and engineering, including software defects such as failures of built-in safety alarms [fda_ipii].
  • Process plants. The U.S. Chemical Safety Board found that the 2007 T2 Laboratories explosion, which killed four employees and injured 28 people at nearby businesses, was a runaway reaction that most likely followed an inadequate reactor cooling system [csb_t2].
  • Security protocols. Systematic testing of TLS libraries found state-machine bugs that had gone unnoticed for years, including SKIP-TLS and FREAK, where a network attacker could skip handshake messages. The authors trace them to incorrect compositions of individually correct state machines [beurdouche2015, ncc_smack].

Industry has shown that this class of error can be found before deployment. Amazon Web Services has model-checked the designs of critical systems since 2011 and reports finding subtle bugs that testing missed [newcombe2015]. Tools such as SPIN [holzmann1997], which made model checking of protocols like Peterson's mutual exclusion [peterson1981] routine, TLA+, Alloy and Verus [lattuada2023] are mature. The barrier is that the domain model, the specification, the protocol model and the executable logic usually live in different tools and drift apart.

2The language and toolchain

bil keeps all four in one file. A program can contain:

  • Ontology: concept hierarchies with <: subtyping, algebraic data types, and first-order axioms over them.
  • Specified functions: fn with requires and ensures, written in Dijkstra's guarded command language [dijkstra1975]: if … fi with nondeterministic choice among enabled guards, and do … od loops with an invariant and a variant.
  • Reactive systems: system blocks with typed state, safety invariants, temporal properties (P ~> Q, eventually), an optional terminal condition and interleaved guarded transitions in the style of SPIN/Promela.
  • Data pipelines: |> chains of where, map, sort_by, sum and quantifiers over concrete data.

Verification conditions

For if G₁ → S₁ [] … [] Gₙ → Sₙ fi, bil verify generates guard totality (some guard holds under the precondition) and one obligation per branch, Gᵢ ⇒ wp(Sᵢ, Q). Because the semantics is demonic, a design with overlapping guards must be correct whichever enabled branch runs. For a do … od loop it generates five obligations: invariant initialization, preservation by every branch, non-negativity and strict decrease of the variant, and the postcondition on exit. The formal rules are in docs/SEMANTICS.md.

Each obligation ends in one of three verdicts:

  • PROVED (by z3): the SMT solver [demoura2008] showed the negated condition unsatisfiable.
  • REFUTED: a counterexample, with concrete values recovered from the solver's model, for example { x = 37 }.
  • BOUNDED (n samples): only sampled. bil verify exits with status 1 in that case unless --allow-bounded is given, so sampled evidence is never mistaken for a proof.

Model checking

bil model-check explores every reachable state of a system breadth-first, so each counterexample is a shortest trace. It checks every invariant in every state, reports a deadlock wherever no guard is enabled in a non-terminal state, and checks P ~> Q by decomposing the ¬Q subgraph into strongly connected components under weak fairness: a cycle only counts as a violation if no transition that leaves it stays enabled throughout. Liveness counterexamples are printed as lassos.

Execution

Proof-only constructs are erased before execution. The tree-walking interpreter, the bytecode VM and native binaries built through rustc share checked 64-bit arithmetic, Euclidean division, and limits of 64 nested calls and 100,000 loop steps; differential tests require identical output from all three. At run time, axioms are checked over the concept instances that actually exist (a closed world), while in the SMT encoding they hold over all models (an open world).

3Method

Each use case went through the same six steps.

  1. Draft the model from domain knowledge.
  2. Research and qualify sources. Every requirement, limit or physical constant is traced to a source and graded: A for standards, specifications and regulators; B for peer-reviewed work; C for manufacturer documents and patents; D for secondary sources used only to corroborate. Each entry also records how much of it was actually read. Several standards (ISO 10218, 13851, 13855 and 15622, and IEC 61511) are paywalled. Their figures come from secondary quotations and are marked as such.
  3. Encode each requirement as a contract, loop invariant, system invariant or temporal property, citing its key inline in the source file.
  4. Check with bil verify, bil model-check and all three back ends.
  5. Seed a bug. Each lesson gets a one-line variant in examples/domains/seeded_bugs/ that reproduces a documented failure mode. bil must reject it with a specific counterexample.
  6. Regress. tests/domain_examples.rs requires every model to be fully proved and every seeded bug to be caught. It runs in about nine seconds as part of the local CI gate.

The research corrected four first drafts. The SPE regrowth rates were low by about 15–20%; sensor plausibility used an arbitrary span instead of the NAMUR NE 43 failure bands; the ACC model used a "two-second rule" where the sources give standard minimum time gaps of 0.8–1 s and recommend 1–2 s; and the bank-angle protection forced a roll-back even while the pilot held the stick, which is not how normal law behaves. The model checker also corrected one draft: an MQTT model whose retransmission guard was too strict to expose the bug it was written to show.

Semiconductor manufacturing · lead case

Spectroscopic ellipsometry gating a solid-phase epitaxy anneal

25 obligations proved158 statesAnnealFinishes LTL proved2 seeded bugs caughtsemiconductor_se_spe.bil

Process context

Ion implantation amorphizes a surface layer of a silicon wafer. A thermal anneal then regrows it epitaxially from the crystalline substrate below: solid-phase epitaxy (SPE). Two measurements and one control loop decide whether the result is single-crystal silicon.

  • Metrology before the anneal. Spectroscopic ellipsometry measures the change in polarization, Ψ and Δ, over wavelength [fujiwara2007]. Fitting a multilayer optical model (oxide, amorphous layer, damaged substrate) gives the amorphous layer thickness. The fit has to be trusted with care: with an unsuitable dielectric-function model, ellipsometry can overestimate low-level damage [lohner1996]. SE has been used to follow the regrowth of implant-amorphized silicon [holgado1995].
  • Kinetics of the regrowth. For intrinsic Si the regrowth front moves at v = 4.64×10¹⁶ Å/s · exp(−2.7 eV / kT) [roth1990, johnson2007]. That is about 1.4 Å/s at 550 °C, 12 Å/s at 600 °C and 84 Å/s at 650 °C, so 30 °C of error changes the anneal time by a factor of two or more. Random nucleation in the amorphous layer has a higher activation energy, about 4 eV, so it gains on epitaxy as temperature rises [olsonroth1988, olson1985]. This sets the upper edge of the process window.
  • The thermal hazard. Amorphous Si melts 200 ± 50 K below crystalline Si. Under pulsed heating, a thin liquid layer can then propagate through the amorphous film at 10–20 m/s and leave fine-grained polycrystalline silicon: explosive crystallization [thompson1984]. In rapid thermal processing, temperature non-uniformity during ramps causes slip, which limits how fast the lamps may slew [norman1991, uspto6403925]. Typical RTP ramps run at 20–100 °C/s [uspto6034356].
  • In-situ monitoring. Real-time SE during solid-phase crystallization yields both a near-surface temperature calibration and the crystalline volume fraction over time [fujiwara1998]. This makes an ellipsometric endpoint for the regrowth, and a second temperature channel, practical.

What is modeled and proved

The SE gate accepts a site only when the regression converged, the fit error is under a threshold, and the thickness is inside the implant recipe's expected range. z3 proves the gate is exactly that predicate, with no hidden case:

fn se_site_valid(s: SeSite, mse_max: Int, t_min: Int, t_max: Int) -> Bool
  requires mse_max > 0 && 0 <= t_min && t_min < t_max
  ensures  result <=> (s.converged && s.mse_milli <= mse_max
                       && s.a_si_thickness_a >= t_min && s.a_si_thickness_a <= t_max)
=
  s.converged && s.mse_milli <= mse_max
  && s.a_si_thickness_a >= t_min && s.a_si_thickness_a <= t_max

The wafer disposition is proved for all inputs: fewer than 80% usable sites always sends the wafer back to metrology, and enough sites with a uniform layer always releases it. The regrowth-rate table comes from the Arrhenius law above. Each band uses the rate at its lower edge, so a time computed from it is never optimistic, and z3 proves the rate is zero outside the window and positive inside:

fn spe_rate(temp_c: Int, t_upper: Int) -> Int
  requires t_upper > 650
  ensures  result >= 0 && (temp_c < 550 => result == 0) && (temp_c >= t_upper => result == 0)
           && (temp_c >= 550 && temp_c < t_upper => result > 0)
=
  if temp_c < 550                          -> 0
  [] temp_c >= 550 && temp_c < 600         -> 1
  [] temp_c >= 600 && temp_c < 650         -> 12
  [] temp_c >= 650 && temp_c < t_upper     -> 84
  [] temp_c >= t_upper                     -> 0
  fi

The fast thermal loop is where the hazards meet. Whatever the outer loop demands, the per-tick setpoint stays within the slew limit and never exceeds the hard temperature limit. All five branches are proved, including the case where the demand is above the hard limit while the current setpoint is below it:

fn thermal_setpoint(cur: Int, demand: Int, max_step: Int, t_hard: Int) -> Int
  requires max_step > 0 && cur <= t_hard
  ensures  result <= t_hard && result - cur <= max_step && cur - result <= max_step
=
  if demand > cur + max_step && cur + max_step <= t_hard   -> cur + max_step
  [] demand > cur + max_step && cur + max_step > t_hard    -> t_hard
  [] demand < cur - max_step                               -> cur - max_step
  [] demand >= cur - max_step && demand <= cur + max_step && demand <= t_hard -> demand
  [] demand >= cur - max_step && demand <= cur + max_step && demand > t_hard  -> t_hard
  fi

The anneal itself is a system with temperature in bands. Lamp drift or latent-heat release may push the wafer out of the window at any time during the soak, up to a bounded number of excursions, and the pyrometer may fail at any point. Five invariants are checked in all 158 reachable states, and AnnealFinishes proves under weak fairness that every anneal that starts ramping ends in Done or Reject:

  invariant NeverMeltAmorphousSi:   temp <= 7
  invariant NoAnnealWithoutSe:      (phase == Ramp || phase == Soak) => se_ok
  invariant NoHeatOnPyrometerFault: !pyro_ok => !lamp
  invariant RegrowthOnlyAfterSe:    amorph < 3 => se_ok || phase == Load || phase == Measure
  // Over-temperature only arises from a soak excursion. A pyrometer fault in the middle
  // of one drops straight to Cool with the lamp off, so the wafer can still be at
  // band 7 in Cool (the model checker found that trace for a stricter `phase == Soak`).
  invariant OverTempIsTransient:    temp == 7 => ((phase == Soak || phase == Cool) && excursions >= 1)

On the example wafer W07 the verdict is Rework. Only three of five sites pass the SE gate, which is under 80%, even though the three good thicknesses are uniform (uniform = true, mean 411 Å). At 600 °C that layer needs 35 one-second ticks to regrow, computed by regrowth_ticks, which is proved to terminate with the whole layer consumed.

Limits. Temperature is discretized into bands and time into ticks. A production controller needs dense-time or hybrid analysis of the plant, and the window edge (680 °C here), the fit thresholds and the excursion budget are example recipe parameters, not recommendations. The model proves the supervisory logic and the per-tick command bounds, not the thermal physics.

Critical process systems

A safety instrumented system for an exothermic reactor

2 obligations proved23 statesTripIsReset LTL proved1 seeded bug caught

The T2 Laboratories explosion was a runaway reaction after a cooling failure [csb_t2]. A safety instrumented system under IEC 61511 [iec61511] is the independent layer meant to stop that sequence. Three temperature transmitters voted 2-out-of-3 tolerate one fault both against failing to trip and against tripping spuriously [lundteigen_sis], at a higher cost and complexity than simpler architectures [kenexis_2oo3]. Both properties are proved for all inputs:

fn high_temp_trip(t1: Int, t2: Int, t3: Int, setpoint: Int) -> Bool
  requires setpoint > 0
  ensures  ((t1 >= setpoint && t2 >= setpoint) => result)
           && ((t1 < setpoint && t2 < setpoint) => !result)
=
  (t1 >= setpoint && t2 >= setpoint) || (t1 >= setpoint && t3 >= setpoint)
  || (t2 >= setpoint && t3 >= setpoint)

The reactor system lets cooling fail at any time. While running, the SIS trips at band 7 and pre-empts further heating, residual heat may add one more step, and the reactor is reset after cooling. The design temperature is never exceeded, and every trip is eventually reset.

Collaborative robotics

Speed and separation monitoring in a cobot cell

8 obligations proved6 statesEStopIsReleasable LTL proved1 seeded bug caught

ISO/TS 15066 defines speed and separation monitoring (SSM) as one of four collaborative modes [isots15066]. NIST has published guidance on implementing its protective separation distance [marvel2017] and built a laser-scanner testbed that stops and restarts a robot from it [szabo2012]. The model takes the protective distance as an input and adds a 500 mm collaborative band capped at the 250 mm/s reduced speed associated with ISO 10218 [iso10218]:

fn ssm_speed_limit(sep_mm: Int, protective_mm: Int, vmax: Int) -> Int
  requires protective_mm > 0 && vmax >= 250 && sep_mm >= 0
  ensures  result >= 0 && result <= vmax
           && (sep_mm <= protective_mm => result == 0)
           && (sep_mm < protective_mm + 500 => result <= 250)
=
  if sep_mm <= protective_mm                                  -> 0
  [] sep_mm > protective_mm && sep_mm < protective_mm + 500   -> 250
  [] sep_mm >= protective_mm + 500                            -> vmax
  fi

The cell supervisor lets the human move between zones at any moment, with the scanner's safety output acting in the same step. Four invariants hold in every state: standstill in the protective zone, reduced speed in the shared band, E-stop means stop, and a valid zone.

What the checker found

The first draft claimed that a protective stop always clears. It cannot, because the human may stay in the protective zone, or press E-stop again, forever. The checker returns that as a fair lasso. What the controller can promise is that a latched E-stop is always releasable, and that is now proved.

Control systems

Fixed-point PI control with anti-windup

When an actuator saturates, an integrator keeps accumulating and the loop behaves as if open. Conditional integration and back-calculation are the two standard remedies [scilab_aw, astrom_murray]. The model proves, for all integer inputs as on a PLC, that saturation stays in the actuator range, that the conditionally integrated state stays bounded, and that a rate-limited setpoint ramp never overshoots and lands exactly on target:

fn ramp_to(start: Int, target: Int, rate: Int) -> Int
  requires rate > 0
  ensures  result == target
=
  do r = start
    invariant (start <= target => (r >= start && r <= target))
              && (start > target => (r <= start && r >= target))
    variant   abs(target - r)
  :
     r < target && target - r > rate  -> r := r + rate
  [] r < target && target - r <= rate -> r := target
  [] r > target && r - target > rate  -> r := r - rate
  [] r > target && r - target <= rate -> r := target
  od
  then r

A hysteresis thermostat system keeps the temperature in its comfort band, and two liveness properties prove the heater never latches on or off.

Signals with emergency preemption, a level crossing, and dispatch triage

A conflict monitor or malfunction management unit forces an intersection into flash when it sees conflicting greens [mmu]. The MUTCD requires a steady yellow after every green and leaves red clearance to engineering practice [mutcd4d26]. The intersection model proves no conflicting greens, the property the monitor enforces in hardware, in every state, including during emergency preemption. It also proves that preemption ends and that north–south traffic is served.

The level crossing follows Heitmeyer and Lynch's Generalized Railroad Crossing benchmark [heitmeyer1994]: the gate is down whenever the crossing is occupied, and it reopens once the train has gone. The siting assumption, that the gate is down before a train can arrive, is written as an explicit guard rather than hidden. Dispatch triage is a proved scoring function and a pipeline over an incident queue.

system LevelCrossing {
  state train: Int = 0
  state gate: Gate = Up

  invariant GateDownWhenOccupied: train == 2 => gate == Down
  invariant TrainRange:           train >= 0 && train <= 2

  temporal GateReopens: (train == 0 && gate == Down) ~> (gate == Up || train == 1)

  transition
     train == 0                    -> train := 1, gate := Lowering
  [] gate == Lowering              -> gate := Down
  [] train == 1 && gate == Down    -> train := 2
  [] train == 2                    -> train := 0
  [] train == 0 && gate == Down    -> gate := Up
}

6Cross-cutting lessons

  • Liveness often belongs to the environment. In the cobot cell and the infusion pump, the natural liveness claim ("the stop clears", "the alarm clears") was false, because a person or a recurring hazard controls it. The checker separates what the controller can guarantee from what it cannot, which is the distinction a hazard analysis needs.
  • Protocols carry hidden assumptions. MQTT's exactly-once guarantee is only as good as in-order transport. Writing the assumption as a guard means that deleting it produces a counterexample instead of silently weakening the proof.
  • Response time is a safety property. In the reactor and the SPE anneal, a protection function that was logically correct but one step slower than the hazard was unsafe. Interleaving semantics finds these races without a timing model, as long as the race is modeled as a choice.
  • Counterexamples also find over-strong requirements. The SPE invariant was wrong, not the design. A refuted property is a question to answer, and sometimes the answer is to fix the specification.
  • Formal models need primary sources. Four drafts changed after research, and in each case the model was internally consistent and verified before the correction. A proof shows that the model meets its specification. Only sources show that the specification matches the world.

7Limitations and threats to validity

  • Abstraction. Continuous quantities are integer bands and time is discrete steps. Claims are about supervisory logic and per-step bounds. Dense-time and hybrid properties need timed or hybrid automata.
  • SMT encoding. Calls to user-defined functions inside a contract are not unfolded into the SMT query. The 2oo3 trip written as a call to vote_2oo3 is only bounded-checked, so the shipped model inlines it. The seeded file reactor_trip_via_call.bil documents this.
  • Bounded cross-check cost. The bounded sampler that runs beside SMT enumerates the product of every parameter's sample domain. A function with a record and four integer parameters took 59 seconds to verify in a debug build, so the navigation model passes records instead. A sample cap is on the roadmap.
  • Arithmetic. SMT reasons over unbounded integers, while execution uses checked 64-bit integers that stop on overflow. Proofs therefore cover the intended mathematics, and execution fails loudly outside it.
  • Sources. Several standards were read only through secondary quotations, and those figures are marked in the citations. Parameters in the models are illustrative, not compliance values.
  • Assurance. bil is not a qualified tool under IEC 61508, ISO 26262, IEC 62304 or DO-330, and these models have not been reviewed by domain safety assessors. They demonstrate method, not certification evidence.

8Roadmap

  • Unfold or inline non-recursive user functions in the SMT encoding, so contracts can call helpers.
  • Cap and randomize the bounded cross-check, with the sample budget reported.
  • Clocks and timed guards in system blocks, for response-time properties that are currently encoded as priority.
  • A refinement path from banded models to continuous controllers, ending in Verus-checked Rust through bil emit-verus.
  • Tool-qualification evidence: requirements tracing, coverage and independent test suites for the verifier itself.
