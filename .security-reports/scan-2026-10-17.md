## What Your Code Does RIGHT

> Security strengths found in this codebase. These are good practices to preserve and extend.

### 1. Rust & Verus Codegen Identifier/Literal Sanitization — `src/codegen.rs:21`, `src/verus.rs:355`
`sanitize_rust_ident` strips non-alphanumeric characters and prefixes Rust reserved keywords (`r_`), while all emitted string and concept literals use Rust debug formatting (`{:?}`), preventing arbitrary Rust code injection during `bil build` and `bil emit-verus`.

### 2. SMT-LIB2 Identifier Sanitization & Quote Escaping — `src/smt.rs:500`, `src/smt.rs:801`
`sanitize_smt_ident` restricts SMT identifiers to `[A-Za-z0-9_-]` and `expr_to_smt` escapes embedded double quotes (`s.replace('"', "\"\"")`), preventing SMT-LIB2 command injection (`(exit)`, `(get-value ...)`).

### 3. Exclusive Temporary File Creation (`O_CREAT | O_EXCL`) — `src/codegen.rs:801`
`compile_native_binary` creates intermediate `.rs` files in `std::env::temp_dir()` using `fs::OpenOptions::new().write(true).create_new(true)` combined with `process::id()` and a monotonic `AtomicU64` counter, neutralizing symlink/TOCTOU hijacking in shared `/tmp` directories.

### 4. Parameterized Subprocess Execution (No Shell Interpolation) — `src/smt.rs:336`, `src/codegen.rs:825`
External binaries (`z3`, `cvc5`, `vampire`, `rustc`) are spawned directly via `std::process::Command::new(&bin_path).args(...)` with piped `Stdio` rather than `sh -c`, preventing shell metacharacter injection.

### 5. Wall-Clock Subprocess Timeout & Forced Termination — `src/smt.rs:375`
`run_single_binary` polls `child.try_wait()` against a configurable wall-clock timeout (`BIL_SOLVER_TIMEOUT_MS`, default `6000 ms`) and invokes `child.kill()` + `child.wait()` on expiry, preventing denial-of-service from non-terminating quantifier instantiations.

### 6. Pratt Parser & S-Expression Nesting Depth Guards — `src/parser.rs:17`, `src/ontology.rs:321`
Both `Parser::parse_expr` (`MAX_PARSE_DEPTH = 128`) and `parse_one_sexpr` (`depth > 128`) enforce strict recursion caps, preventing call-stack exhaustion on deeply nested untrusted `.bil` or `.logic` inputs.

### 7. Tree-Walk Interpreter Recursion & Loop Iteration Fuel — `src/eval.rs:15`
`Interpreter` enforces `MAX_EVAL_CALL_DEPTH = 256` and `MAX_DO_OD_ITERATIONS = 100_000`, preventing host stack overflow and unbounded loop hangs.

### 8. Bytecode VM Instruction Fuel & Frame Depth Limits — `src/vm.rs:101`
`BytecodeVm::execute` enforces `MAX_VM_STEPS = 1_000_000` and `MAX_VM_CALL_DEPTH = 256`, bounding resource usage during bytecode execution.

### 9. Checked 64-Bit Euclidean Arithmetic Across All Backends — `src/eval.rs:395`, `src/vm.rs:237`, `src/runtime_prelude.rs:138`
All three execution engines (`eval`, `vm`, and Native AOT `runtime_prelude.rs`) use `checked_add`, `checked_sub`, `checked_mul`, `checked_div_euclid`, and `checked_rem_euclid`, preventing silent integer wraparound or divide-by-zero panics.

### 10. Bounded Explicit-State Model Checking — `src/model_check.rs:161`
`model_check_system` bounds BFS state-space exploration via `max_states` (default `50,000`) and explicitly reports truncation via `complete: false` and `truncated_at`.

### 11. Zero `unsafe` Rust Code — `src/lib.rs:1`
The entire crate (`src/**/*.rs` and `tests/**/*.rs`) contains zero `unsafe` blocks, relying strictly on safe Rust memory and thread-safety guarantees.

### 12. Minimal, Vulnerability-Free Dependency Tree — `Cargo.toml:16`

### [MEDIUM 5.3] Unbounded Source File Allocation in CLI Reader — `src/cli.rs:35`
**OWASP**: A05 — Security Misconfiguration (CWE-400: Uncontrolled Resource Consumption)
**Layer**: Backend (CLI Entrypoint)
**CVSS**: 5.3 (AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:N/A:H)

**Evidence** (insecure):
```rust
fn read_source_file(path: &str) -> Result<String, i32> {
    fs::read_to_string(path).map_err(|e| {
        eprintln!("Failed to read {}: {}", path, e);
        1
    })
}
```

**Risk**: Passing a multi-gigabyte file or special device stream (e.g., `/dev/zero`) to `bil check` or `bil run` causes `fs::read_to_string` to allocate unbounded heap memory before the lexer or parser can reject the input, resulting in an immediate Out-Of-Memory (OOM) process abort.

**Fix**: Enforce a maximum source file size cap (e.g., `16 MiB`) using `io::Read::take` before reading into memory:
```rust
const MAX_SOURCE_BYTES: u64 = 16 * 1024 * 1024;

fn read_source_file(path: &str) -> Result<String, i32> {
    let file = fs::File::open(path).map_err(|e| {
        eprintln!("Failed to read {}: {}", path, e);
        1
    })?;
    let mut buf = String::new();
    let bytes = file
        .take(MAX_SOURCE_BYTES + 1)
        .read_to_string(&mut buf)
        .map_err(|e| {
            eprintln!("Failed to read {}: {}", path, e);
            1
        })?;
    if bytes as u64 > MAX_SOURCE_BYTES {
        eprintln!("Failed to read {}: file exceeds maximum size ({} bytes)", path, MAX_SOURCE_BYTES);
        return Err(1);
    }
    Ok(buf)
}
```

**References**: [CWE-400: Uncontrolled Resource Consumption](https://cwe.mitre.org/data/definitions/400.html)

### [LOW 3.3] Native AOT Generated Functions Lack Recursion Depth Guard — `src/codegen.rs:133`
**OWASP**: A05 — Security Misconfiguration (CWE-674: Uncontrolled Recursion)
**Layer**: Backend (Native AOT Codegen & Runtime Prelude)
**CVSS**: 3.3 (AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:N/A:L)

**Evidence** (insecure):
```rust
fn bil_fn_{}(args: Vec<BilVal>, globals: &BTreeMap<String, BilVal>) -> BilVal {
    let mut env = globals.clone();
    ...
    {}
}
```

**Risk**: While the tree-walk interpreter (`MAX_EVAL_CALL_DEPTH = 256`) and bytecode VM (`MAX_VM_CALL_DEPTH = 256`) bound recursion depth, Native AOT binaries generated by `bil build` execute recursive `bil_fn_*` calls directly on the OS stack without a depth counter or `do..od` iteration cap, allowing an unverified non-terminating program to trigger an OS stack overflow (`SIGSEGV`) or hang.

**Fix**: Add a thread-local call depth guard in `src/runtime_prelude.rs` (matching `MAX_VM_CALL_DEPTH = 256`) and a loop fuel counter in emitted `do..od` loops.

**References**: [CWE-674: Uncontrolled Recursion](https://cwe.mitre.org/data/definitions/674.html)

### [LOW 3.3] Unvalidated Compiler Binary Path Override (`BIL_RUSTC_PATH` / `RUSTC`) — `src/codegen.rs:822`
**OWASP**: A08 — Software and Data Integrity Failures (CWE-426: Untrusted Search Path)
**Layer**: Backend (Native AOT Subprocess)
**CVSS**: 3.3 (AV:L/AC:L/PR:L/UI:N/S:U/C:L/I:L/A:N)

**Evidence** (insecure):
```rust
let rustc_bin = std::env::var("BIL_RUSTC_PATH")
    .or_else(|_| std::env::var("RUSTC"))
    .unwrap_or_else(|_| "rustc".to_string());
let status = Command::new(&rustc_bin)
```

**Risk**: Unlike `find_solver_binary` in `src/smt.rs:119-123` (which trims whitespace and verifies `p.is_file()` before returning an environment override), `compile_native_binary` passes `BIL_RUSTC_PATH` / `RUSTC` directly to `Command::new` without trimming or checking `is_file()` when an override path is specified.

**Fix**: Trim and validate `BIL_RUSTC_PATH` / `RUSTC` overrides consistently with `find_solver_binary`.

**References**: [CWE-426: Untrusted Search Path](https://cwe.mitre.org/data/definitions/426.html)
